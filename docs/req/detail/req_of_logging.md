# ロギングの要求

**文書 ID**: `req_of_logging`

本書はコマンド実行時に利用者へ提示すべき進捗・結果・警告・エラーの出力要求を定義する。用語は [req_of_terms.md](req_of_terms.md) に従う。

---

## 1. 方針

| 項目 | 要求 |
|------|------|
| 目的 | 設定パスの確認、処理段階の把握、個別失敗の特定、完了の明示 |
| フレームワーク | 現行要求では標準の `logging` モジュール利用を必須としない。標準出力へのメッセージ出力で満たしてよい |
| 言語 | 段階見出しは英語でも日本語でもよいが、エラー・警告は原因が分かる文言であること |
| 機密 | 認証情報等の秘密情報を出力しないこと |

---

## 2. 重大度（論理レベル）

実装が `print` のみであっても、次の論理レベルを区別できること。

| 論理レベル | 用途 | 例となる状況 |
|------------|------|--------------|
| INFO | 通常の進捗・成功 | 完了 |
| WARNING | 続行可能な異常 | ディレクトリ作成の失敗、ファイル作成の失敗 |
| ERROR | 当該項目の失敗（全体は継続可） | 書込失敗 |

未捕捉例外時のトレースバックは言語ランタイムの標準出力先に従うこと。

---

## 3. 出力先

| 種別 | 要求 |
|------|------|
| INFO / WARNING / ERROR（利用者向けメッセージ） | 標準出力でよい |
| argparse の用法・引数エラー | 標準エラー（argparse 標準で可） |
| 未捕捉例外のトレースバック | 言語標準（通常は標準エラー） |

---

## 4. 非要求（現行スコープ外）

次は現行要求では必須としない。

- ログレベルを CLI オプションで切り替えること
- ログファイルへの永続化
- 構造化ログ（JSON 等）
- ロガー名空間の階層化
